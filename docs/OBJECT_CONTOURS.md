# 按真实轮廓提取对象（2026-10-15）

本轮目标是减少矩形切片、对象碎裂和文字被图片裁切。不是另建 pipeline，不改变 UI，也不承诺复杂截图全部矢量化。

## 原因与修改

旧流程按分割面积从小到大分配所有权，将同一叠放照片的内部、边框分别提取；高密度 mask 被重新变为实心矩形；VLM 模块 bbox 直接切原图，可能切断横幅和文字。子对象提取后，卡片还会留下透明洞。

- `contour_objects.py`：合并近似重复的内外轮廓，保留完整紧凑视觉；大型卡片允许独立子对象。补充彩色通道闭合轮廓，识别浅色圆角卡片。拒绝切过尚未转原生的 OCR 行的提案。
- `visual_assets.py`：bbox 只作搜索范围，不自动成为不透明边界；用真实轮廓、局部底色估计、抗锯齿和边缘颜色去污染生成透明 PNG。恢复仅检测到山脊等稀疏边缘对应的完整视觉。无法可靠估计时保留完整裁片，标记 `matteNeedsReview`，不删掉未知内容。
- `exclusive_ownership.py`：VLM 模块只负责语义分组，不授权矩形裁切；文字原生化和资产落盘验证后才清理对应字形。独立子对象下的底板，仅在可测得可靠底色时补齐，且不重新拥有子对象的源像素。未被覆盖的少量字形晕边底材只交给一个已有 carrier。
- `editable_text.py`：渐变文字可能只有浅色部分进入旧字形掩码，金色数字脚部残留。新增 OCR 框内、与已验证字形连接且颜色方向相符的扩展，保留面积/横线限制，不擦整个框；字体匹配不变。
- `reconstruction_quality.py`：新增透明轮廓资产数、不确定 matte、未完成底板和补齐像素统计。沿用无 owner 不删除、无重复原字、非文字内部像素保留和缺失资产检查，没有放宽失败门槛。

## 分割与数据契约

继续使用现有 Ultralytics SAM2 / OpenCV adapter。当前机器实际运行了本地 SAM2，权重位于 LOCALAPPDATA 下，不进入源码或 Drive。本轮没有新增收费 API 调用：重放此前真实 OCR/Qwen 记录，并对科研图4实际重跑 SAM2。不存在伪造识别正文。

所有结果仍由同一 Layout/Scene Graph 驱动 editor、preview 和 PPT。资产包含透明 alpha；`owner`、`parent/groupId`、`zIndex`、`source`、`reconstructionStrategy` 沿用现有协议。新增 `contourPlanning`、`boundaryAuthority`、`absorbedContourProposals` 和底板修补证据，便于审查决策。

保留的旧文字只能属于图片 owner；转原生的文字必须整行通过验证，不能在图片中再次保留。LaMa 没有用于整块清洗；本轮 exclusive 路径 inpaintCalls=0，使用的是经验证的字形局部底材。

## 真实验证

每次验证均生成隔离的诊断输出，不覆盖用户已有结果；没有连续自动优化。

- 科研图4：`bd4a9b4e2c484d9ca229ce00db34f8c8`。92 原生文本框、51 图片 owner；34 个轮廓透明资产。66/77 条完整 OCR 行可编辑，字符覆盖率 78.7281%；原先可编辑行无退化。
- 科研图2：`fcfdedf9db8248da8224e2a76505d1a4`。64 原生文本框、51 图片 owner；40 个轮廓透明资产。41/52 条完整 OCR 行可编辑，字符覆盖率 77.2939%；原先可编辑行无退化。
- 党建复杂图：`8345a0efc1a748af8f2fd3c092ffed55`。94 原生文本框、37 图片 owner；9 个轮廓透明资产。77/99 条完整 OCR 行可编辑，字符覆盖率 82.7027%；渐变数字残留检查通过。

三页均通过资产存在、原字重复、源像素唯一 owner、原生文字底材覆盖及非文字内部像素保留检查。重新打开 PPT 后原生字符串与 Layout 一致；这不等于源图文字 100% 被识别或可编辑，也不等于字体完全一致。

实际 Chromium 验证科研图4中央五条文字的六个文本段双击修改，以及图片拖动、缩放；浏览器异常、媒体 404、Fabric 重复原生文字像素均为 0。PowerPoint 实际只读打开并渲染最终 PPT 和删除原生文字后的诊断 PPT。

后端全套：450 passed、2 个第三方弃用警告。Ruff E9/F/I、TypeScript check、Vite build、git diff --check 通过；仍有既有 607.09 kB bundle 提示。

## 如何检查结果

`scripts/inspect_object_assets.py <输出项目目录> --compare <旧输出项目目录>` 将实际 PNG 放在棋盘底上，输出 `asset_contact_sheet.png`、`object_before_after.png` 和对应资产 ID；不会用 AI 重画掩盖真实边缘问题。

`scripts/verify_native_recovery.py <已有输出项目目录>` 重放保存的真实证据；`--refresh-segmentation` 才重新调用本地分割器。`--require-text-id` 可验证指定 OCR 行仍完整可编辑。

## 仍未解决

- 山形、半透明渐变和柔软阴影在复杂底色上仍可能出现硬边或浅色晕边，不能声称全部无毛刺。
- 科研图4还有 4 个 matte 不确定资产、15 个底板存在未可靠补齐的遮挡区域；科研图2分别为 1/17，党建为 8/7。移动对象后有些底板仍会露出空缺，不能凭空恢复被遮挡纹理。
- 以上复杂页仍有文字保留在图片中；字体替代及 OCR 将图案识别为单字符的问题尚在。科研图4 Proposed 图案附近的 H 就需要继续审核。
- 本轮主要改善独立 PNG 的轮廓和完整性，没有把这些复杂图片伪称为原生 Shape，也没有重做 UI。
- 像素保留 QA 是有限证据，不代表语义对象提取完美。后续应优先完善软边 matte、遮挡底板建模和对象级人工确认，不能通过放松 QA 或循环擦除来追求表面干净。
