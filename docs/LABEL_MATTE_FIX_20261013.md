# 2026-10-13：混合文字排版与透明资产完整性修复

## 基线与范围

- 用户文件 `editable (11).pptx` 的 slide1.xml 与本地记录 `77e91ec71e7d43a4a5fe71b0d7a6fca1` 完全匹配。
- GitHub 基线：`codex/text-integrity-quality` / `b901cb38802fe139e9406286a9b8c0e58cae6aa9`；已执行 push 并用 ls-remote 确认一致。
- 修复分支：`codex/label-matte-fidelity`。不覆盖用户原文件、手工编辑结果，不执行自动优化轮次，不修改 UI。
- 使用已保存的真实 OCR/Qwen/SAM 证据做确定性回放，没有伪造识别，也没有新增付费 API 调用。候选另存于 outputs。

## 根因

1. 字体匹配将每个候选字形拉伸到目标尺寸后打分，但 PPT 导出的是未拉伸字形，导致分数与实际字号/笔画不一致。
2. 旧算法允许 -0.15em 字距，右下角定义文字实际用了 -3.75px。标签与正文存在字号差异却被压为一个文本框。
3. 混合文本只在字号跨度很大时拆分，中文标签与英文术语、冒号两侧的字体差异容易被忽略。
4. SAM 轮廓被当成完整物体，细小连通部件与抗锯齿边缘可能分给别的资产；原位拼接的成功不能证明独立移动后的完整性。
5. Pixel ownership 检查没有表示字体相似度，不能据此声称高保真。

## 修改

- `backend/app/services/reconstruction/editable_text.py`：使用不拉伸的实际字形评分；负字距限为 -0.055em；补充可选本机 Noto 中文字体；符号/标点的墨迹高度不再等同于字号。
- `backend/app/services/reconstruction/mixed_text.py`：增加有像素证据的标签/正文、混合文字样式分段；两段都必须通过 Owner 验证且确实优于整行；保留 OCR 原文、字符区间；失败时保留原有可靠整行或图片，不提交半句。
- `backend/app/services/typography/font_raster.py`：可变字体按请求字重测量，不能使用 Noto 的默认 Thin 字重冒充 Bold；预览和匹配共用字体实现。只读取系统字体，不复制字体文件到仓库。
- `backend/app/services/reconstruction/visual_assets.py`：恢复与 SAM 种子连通的源图细节；模糊边缘先验证在实测底色上的复合结果；不允许平滑吃掉内容；去掉采样扩张到纯底色产生的半透明白边。证据不足仍保留真实局部裁切。
- `backend/app/services/validation/reconstruction_quality.py`：增加字体近似警告、过度负字距数量和分割细节恢复像素数。没有将这些指标冒充语义完整性或 WPS 验收。
- `backend/tests/test_label_and_matte_fidelity.py`：新增异字号标签、细小附属部件、可变字重、小符号和字体 QA 测试。同步已有测试的可选参数。
